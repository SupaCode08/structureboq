## 2. สิ่งที่แก้ไปแล้ว (รายไฟล์)

### 2.1 ตัวอ่าน OCR แบบสแกนใหม่ — PaddleOCR (PP-OCRv4) บน onnxruntime-web

- **แพ็กเกจใหม่** (ผู้ใช้อนุญาตแล้ว): `onnxruntime-web@1.30.0`, `@gutenye/ocr-models@1.4.2` (มีไฟล์ `ch_PP-OCRv4_det_infer.onnx` 4.7 MB, `ch_PP-OCRv4_rec_infer.onnx` 10.8 MB, `ppocr_keys_v1.txt`)
  - ติดตั้งด้วย `npm install --legacy-peer-deps` เพราะโปรเจกต์มี peer conflict เดิมอยู่แล้ว (esbuild 0.25 vs vite 8 ต้องการ 0.27+) ไม่เกี่ยวกับแพ็กเกจใหม่
  - ไม่ใช้ `@gutenye/ocr-browser` / `ocr-common` (ผูกกับ canvas/opencv และมีบั๊ก) — ถอนออกแล้ว
- **`src/pdf/paddleOcr.ts`** (ใหม่, ~150 บรรทัด) ทำงานเหมือนกันทั้ง Node และเบราว์เซอร์
  - `loadPaddle(ort, detBytes, recBytes, dictText)`
  - `paddleWords(paddle, raster)` → คำพร้อมกรอบ (normalized 0..1), มี `vertical`
  - ขั้นตอน: blur 3×3 (ภาพสแกนขาวดำ ทำให้เลข "1" บาง ๆ ไม่หาย) → detection แบ่ง tile 960 px ซ้อน 96 → probability map → หา connected region (เกณฑ์ 0.3, ค่าเฉลี่ยของ region เองต้อง ≥ 0.6, ขยายกรอบแบบ DB unclip 1.5) → recognition ทีละกรอบที่สูง 48 px, ถอดรหัส CTC, แยกคำด้วยช่องว่าง, กรอบคำคำนวณจากตำแหน่ง timestep
  - กรอบที่สูงกว่ากว้าง 1.5 เท่าอ่านแบบหมุน และลองอ่านแบบไม่หมุนด้วยถ้าไม่สูงมาก
  - รอบที่สอง: หมุนภาพ 90° ตามเข็มแล้วอ่านซ้ำ เพื่อจับตัวเลขแนวตั้ง (เช่นความลึกคาน "0.40") แล้วแปลงกลับด้วย `unrotate` จาก `ocr.ts`
- **`src/pdf/pdfOcrPipeline.ts`**
  - `OcrEnv.readScan?(raster)` — ถ้ามี หน้าสแกนอ่านด้วย Paddle รอบเดียว บน **ภาพที่เตรียมแล้ว** (Otsu, แก้เอียง, ลบเส้นบอกระยะ) จาก `renderPage(..., prepared=true)` ซึ่งต้องคืน `raster`
  - ถ้า Paddle ล้ม (throw) จะ `console.warn` แล้วกลับไปใช้ลูป tesseract เดิม 4 รอบ
  - แยกฟังก์ชัน `deskewed()` ออกมา (ใช้กับรอบ raw ของ tesseract)
- **`src/pdf/paddleWorker.ts`** (ใหม่) worker สำหรับเบราว์เซอร์ รับ `{id, raster, urls}` คืน `{id, words | error}`; ตั้ง `ort.env.wasm.numThreads = 1`
- **`src/pdf/browserPipeline.ts`**
  - import URL ของโมเดลแบบ `?url` จาก `node_modules/@gutenye/ocr-models/assets/...` → Vite รวมเป็น asset ในแอป (ไฟล์ไม่ออกนอกเครื่อง)
  - `readScan()` แบ่งภาพเป็นแถบแนวนอน N = min(4, cores−1) แถบ ซ้อนกันข้างละ 200 px ส่งให้ worker ละแถบ แล้วเก็บคำเฉพาะจากแถบที่ "แกน" ครอบจุดกึ่งกลางคำ
  - หน้าสแกนเรนเดอร์ที่ 400 dpi (`renderForOcr(pg, 400/72, …)`) ให้ตรงกับ Node; `renderForOcr` คืน `raster: prep`
  - worker ล้มตอนเริ่ม (event `error`) → reject → หน้า fallback ไป tesseract
- **`scripts/offline_ocr.ts`** โหลด Paddle จาก `node_modules/@gutenye/ocr-models/assets/` (ปิดได้ด้วย `PADDLE=0`) ส่ง `readScan`; บันทึก engine เป็น `paddleocr + tesseract.js (offline)`
- **`scripts/scanImage.ts`** `embeddedImage(... prepared)` คืน `raster: prep` เพิ่ม
- **แคช OCR** แทนหน้าสแกนด้วยผลใหม่แล้วใน `real_drawings/{cdc_1,cdc_2,cdc_3,toilet_604_45,house_ready_3}/offline_ocr.json` (แคชเดิมสำรองไว้แค่ในโฟลเดอร์ scratchpad ชั่วคราวของเซสชัน — ถือว่าไม่มีสำรองถาวร)

### 2.3 เสาเข็ม (ครบทั้งสาย อ่าน → รวม → เอนจิน → เทียบ BOQ)

- **`src/pdf/sheetReader.ts`** ในหน้าตัดฐานราก: หาโน้ตขนาดเข็ม `WxWxL` (regex `PILE_SPEC`, ความยาว ≥ 1.5 ม.) ที่อยู่เหนือชื่อฐาน ซ้าย 0.11 – ขวา 0.3 ของหน้า เลือกอันใกล้ชื่อที่สุด แล้วหาเลขจำนวนเต็มบนบรรทัด **เหนือ** โน้ตขนาด (รูปแบบแบบไทย "…จำนวน N ต้น" / "ขนาด ◻ 0.15x0.15x6.00 ม.") → `pile_count`, `pile_size`; ไม่ใช้เลขบรรทัดเดียวกันเพราะ "ม." มักถูกอ่านเป็น "3"
- **`src/engine/sheetMerge.ts`** `SectionDef.pile_count / pile_size`; ฐานรากได้ `pileCount`; ถ้าใช้ผังฐานรากแบบเข็มแต่อ่านจำนวนเข็มไม่ได้ → `fieldSources.piles = 'missing'`
- **`src/engine/qsEngine.ts`** `pilesNos = count × pileCount` (เก็บไว้แม้ฐานถูกปฏิเสธเพราะความหนาอ่านไม่ได้)
- **`src/engine/boqCompare.ts`** รวมเป็น `piles_nos` (คีย์เดิมที่ BOQ parser มีอยู่แล้ว)
- **`scripts/benchmark_offline.ts`** ตัวเลือก `--footing=เข็ม` รันแบบฐานเข็ม (เลือกผังและ variant BOQ) — ระวัง: คำสั่งนี้เขียนทับ `benchmark_offline.json` ของชุดนั้น ให้รัน `npm run benchmark:offline` ปกติหลังทดลอง
- เทสต์: `sheetDetails.test.ts` (โน้ตเข็มสองฐาน), `qsEngine.test.ts` (จำนวนเข็ม)

## 4. งานที่ยังค้าง (เรียงตามความสำคัญ)

1. **ลดค่าที่ผิดในชุดสแกน** (ปัญหา 1) — เริ่มที่ `toilet_604_45` และ `cdc_1` ด้วย `npx tsx scripts/eval_reading.ts real_drawings/toilet_604_45 --detail`; ห้ามปรับโดยดู cdc_2/cdc_3
2. **ความเร็ว** — ทางเลือกที่ยังไม่ได้ลอง:
   - ข้ามรอบแนวตั้งในพื้นที่ที่ไม่มีข้อความ หรือรันรอบแนวตั้งเฉพาะ tile ที่มีกรอบสูงแคบจากรอบแรก

   - ทำ prepareScan/removeLines ใน worker แทน main thread (main thread ใช้ ~16 วินาทีต่อหน้า)
   - วัดนำเข้า ศพด. ทั้งไฟล์ในเบราว์เซอร์จริงก่อนตัดสิน
