# การอ่านแบบโครงสร้าง ค.ส.ล. — หลักที่ระบบใช้ และสิ่งที่ยังไม่ได้ทำ

เอกสารนี้สรุปวิธีที่คนอ่านแบบ (วิศวกร/ผู้ประมาณราคา) ใช้จริง และบอกว่าระบบทำตามข้อไหนแล้ว
ใช้เป็นหลักในการพัฒนา — แก้ระบบตามหลักการอ่านแบบ ไม่ใช่ตามค่าของตัวอย่างใดตัวอย่างหนึ่ง

## 1. ลำดับที่คนอ่านแบบ

1. **สารบัญแบบ / title block** — รู้ว่าแผ่นไหนเป็นผังอะไร มาตราส่วนเท่าไร (แต่มาตราส่วนที่เขียนอาจผิดเมื่อพิมพ์ย่อ)
2. **รายการประกอบแบบ (general notes)** — กำลังคอนกรีต ชั้นเหล็ก ระยะหุ้ม ระยะทาบ สัญลักษณ์เหล็ก
3. **ผัง (plan)** — กริด + ระยะ, ตำแหน่งและเบอร์ของชิ้นส่วน (F1, C1, GB1 …) ผังไม่บอกหน้าตัด
4. **ตาราง (schedule) หรือแบบขยาย (detail/section)** — หน้าตัดและเหล็กของแต่ละเบอร์
5. **รูปตัดอาคาร** — ระดับชั้น ความสูงเสา
6. **ตรวจไขว้** — ตัวเลขกับรูปที่วาดตามมาตราส่วน, เบอร์ในผังต้องมีแบบขยาย, แบบขยายต้องมีในผัง

แหล่งอ้างอิง: ACI 315 / SP-66 (ตารางคานต้องมี mark, ขนาด, จำนวนและขนาดเหล็ก, ปลอก; ตารางฐานรากมีขนาด ความหนา เหล็กล่าง/บน),
คู่มือการอ่านแบบโครงสร้างทั่วไป (ผังบอกเบอร์ ตาราง/รูปตัดบอกรายละเอียด), งานวิจัยดึงข้อมูลจากแบบ (YOLO + OCR + ตรวจความสอดคล้องด้วย knowledge graph;
การหา section view อัตโนมัติยังได้แค่ ~64%)

## 2. รูปแบบที่ต่างกันระหว่างสำนักงาน (เจอจริงในชุดตัวอย่าง)

| หัวข้อ | กรมโยธาฯ (บ้าน 1–4) | กรมส่งเสริมฯ (ศพด.) |
|---|---|---|
| มาตราส่วนผัง | 1:50 | 1:100 (ไฟล์เป็นฉบับย่อ → จริง ~1:141) |
| ชื่อฐานราก | มีขนาดในชื่อ `F(0.95x0.95)` | ไม่มี `F1`, ขนาดอยู่ในชื่อแบบขยาย |
| ชื่อแบบขยาย | ใต้รูป `B1`, หรือวงกลมรูปตัด `2–2` | `แบบขยายฐานราก F1`, `แบบขยายเสา C1=C2` |
| เหล็ก | `2Ø16มม`, `ปØ6มม.@0.15` | `2-RB 12 mm.`, `ป- RB6 mm.@0.20 m.` |
| ตะแกรงฐานราก | จำนวน `5+5Ø12มม` | ระยะ `Ø12mm.@0.15m.` |
| ป้ายคาน | บนเส้น / ข้างเส้น / เส้นนำ (leader) | บนเส้น |
| ชนิดไฟล์ | เวกเตอร์ (ตัวอักษรเป็นเส้น) | สแกน ~200 dpi เอียง ~1.5° |

## 3. สิ่งที่ระบบทำแล้ว (หลักทั่วไป)

- มาตราส่วนจากระยะที่วาด ไม่เชื่อตัวเลข 1:xx อย่างเดียว; ตัวเลขบอกระยะที่ OCR หลุดเติมจากช่องว่างที่เหลือ
- แบบสแกน: ขยาย → ทำขาวดำ (Otsu) → แก้เอียง → ลบเส้นยาวก่อน OCR (ให้เหลือแต่ตัวอักษร)
- แก้ตัวอักษรที่ OCR สับสน (8↔B, 6↔G, £↔F, l/i↔1) เฉพาะเมื่อได้เบอร์ที่มีอยู่จริงในชุดแบบ
- วัดรูปทรงตามมาตราส่วน: หน้าตัดคาน/เสา, เสาในผัง, ความหนาฐานรากจากรูปตัด
- ชื่อแบบขยายรวมหลายเบอร์ด้วย `=`
- **กริดจากเส้นที่วาด**: เส้นยาวที่ปลายมีวงกลมชื่อกริด (bubble) = เส้นกริด; ระยะช่องจากตัวเลขบอกระยะที่อ่านได้ แล้ววัดช่องที่เหลือตามมาตราส่วน
- **ฐานรากจากรูปที่วาด**: ที่จุดตัดกริดแต่ละจุด หาเส้นขอบที่ใกล้ที่สุดทั้งสี่ด้าน (ใช้ได้กับเส้นประและเส้นสแกนที่ขาดเป็นช่วง)
  ขนาดที่วัดได้ตรงกับฐานรากเบอร์เดียว (จากแบบขยายหรือชื่อที่มีขนาด) → นับเป็นเบอร์นั้น;
  ถ้าหลายเบอร์วาดขนาดเท่ากัน (สัญลักษณ์) → นับเป็น `F?` ให้ผู้ตรวจเลือกเบอร์ (จำนวนรวมถูก ไม่เดาเบอร์)
- ป้ายเสาที่ตกบนจุดตัดซึ่งไม่มีเสาวาดไว้ (ป้าย "F…,C1" ถูกแยกเป็นสองคำ) ไม่นับเป็นเสา
- **วงกลมชื่อกริดในแบบสแกน**: วงแหวนที่ปลายเส้น (ทดสอบตามแนววงกลม ทนต่อวงที่ขาดในสแกนความละเอียดต่ำ)
  และต้องเรียงเป็นแถวเดียวกัน (วงของแกนเดียวกันอยู่ระดับเดียวกัน) — วงกลมหลงที่ปลายเส้นไม่นับ
- ตัวเลขบอกระยะช่องต้องอยู่บนเส้นบอกระยะเส้นเดียวกัน: ถ้า OCR ทำตัวเลขช่องหาย ระยะรวมที่เขียนไกลออกไปไม่ถูกใช้แทน
- **การเขียนเหล็ก** (`src/pdf/barNotation.ts`): `2-DB16`, `4ø12มม.`, `5+5ø12มม.`, `7+8-DB12`, `RB6@0.20`, `ป-RB6 mm.@ 0.20 m.`,
  `Ø12mm.@0.15m.` รวมรูปที่ OCR อ่านเพี้ยน (ø → 0/8/@/¢/ผู, ป → U/ๆ1, มม. → WU/UU) — ยอมรับเฉพาะเมื่อได้ขนาดเหล็กมาตรฐาน;
  คำที่ OCR แยก ("5+5" "ø12มม.") ต่อกันตามบรรทัด; ø ที่ไม่ระบุชั้นคุณภาพใช้ตามที่ชุดแบบเขียนขนาดนั้น (เช่น `2-RB12` → ø12 = RB12)
- เหล็กหลายกลุ่มในชั้นเดียว (`3-RB12+2-DB16`) และตะแกรงสองทาง (`5+5-DB12`) เก็บตามแบบ ไม่บวกรวม
- ขนาดเหล็กปลอกอ่านไม่ได้แต่อ่านระยะได้ → ใช้ RB6 และติดธงให้ผู้ตรวจยืนยัน
- **ชื่อรูปตัดวงกลม** `(2)–(2)`: หารอยตัดเลขเดียวกันบนรูปด้านยาวของคาน แล้วใช้ชื่อคานใต้รูปนั้น (B2)
- เสาตอม่อที่วาดในผังฐานรากแต่ไม่มีป้าย → `C?` แล้วใช้เบอร์เสาเดียวที่ผังนั้นใช้ (ติดธงตรวจ)
- OCR ตัวอักษรเวกเตอร์สองเครื่องอ่าน (eng และ tha+eng) แล้วเก็บคำที่มั่นใจกว่า — ป้ายไทยปนอังกฤษ เช่น `5+5ø12มม.`
- ไม่เดาค่า: อ่านไม่ได้ → "ไม่พบ" เข้าคิวตรวจ

## 4. การวัดผล (กันการ "แก้ให้ตัวอย่างผ่าน")

- `real_drawings/<ชุด>/answer_key.json` — ค่าที่อ่านด้วยตาจากแบบ ทีละเบอร์ ทีละค่า
- `npx tsx scripts/eval_reading.ts <ชุด…> --detail` — ถูก / **ผิด** / ไม่พบ ทีละค่า (ค่าผิดแย่กว่าไม่พบ เพราะดูน่าเชื่อ)
- ชุดพัฒนา (`split: dev`) ใช้ปรับระบบได้; ชุดทดสอบแยก (`split: heldout`) ห้ามปรับตามค่าของชุดนั้น — ใช้วัดเท่านั้น

## 5. สิ่งที่ยังไม่ได้ทำ (เรียงตามผลที่คาดว่าได้)

1. **อ่านป้ายทีละป้าย** (`src/pdf/labelOcr.ts`, เปิดด้วย `LABELS=1`): จัดเส้นตัวอักษรเป็นป้าย วาดขยายทีละป้ายแล้ว OCR เป็นบรรทัดเดียว —
   อ่านเหล็กได้ดีขึ้นมาก (`4012มม.`, `ๆ179มม.@0.20`) แต่ยังทำชื่อหัวรูปตัวหนาและป้ายติดเส้นนำหาย; บ้าน 4 ถูก 69% เทียบกับ 73% แบบเดิม จึงยังไม่เปิดเป็นค่าตั้งต้น
2. **ฐานรากที่เป็นรูปภาพฝังในแผ่นเวกเตอร์** (โรงจอดรถ) — ต้องหารูปสี่เหลี่ยมจากภาพ และผังกริดแนวเดียว
3. **ตาราง (schedule)** ในแบบสแกน — อ่านเป็นตาราง แถว = เบอร์
4. **เส้นนำป้าย (leader)** โยงป้ายกับชิ้นส่วน
5. อ่านชื่อในวงกลมกริด (1,2,3 / A,B,C) แทนการนับลำดับ
6. OCR ตัวอักษรเล็กในแบบสแกนความละเอียดต่ำยังพลาดมาก (ศพด. สแกน ~200 dpi)
