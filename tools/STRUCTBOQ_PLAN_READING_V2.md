## ขั้นตอนรุ่น 2

```
เปิดไฟล์ ─► P0 สำรวจ (≤1 วิ) ─► P1 คัดหน้า: อ่านมุมกระดาษทุกหน้า (≤2 วิ)
                                     │
                    ┌────────────────┴─────────────────┐
             โหมด A: ผู้ใช้เลือกหน้า           โหมด B: ระบบเลือก S-xx เอง
             (แสดงผล P1 เป็นรายการให้ติ๊ก)       (ผู้ใช้ดู/แก้ได้ภายหลัง)
                    └────────────────┬─────────────────┘
                     P2 อ่านข้อความเฉพาะหน้าที่เลือก (≤6 วิ)
                     P3 ประกอบผัง + แบบขยาย ด้วยทะเบียนตำแหน่ง (≤1 วิ)
```

**P0 สำรวจ** (มีอยู่แล้ว ~1 วินาทีสำหรับ 64 หน้า): text layer, operator list, ชนิดหน้า (เวกเตอร์/สแกน/ข้อความ), จำนวนเส้นตัวอักษร

**P1 คัดหน้า — อ่านมุมกระดาษทุกหน้าก่อน** (ต่างจากตอนนี้ที่คัดทีละหน้าปนกับ OCR ใน lane)
- หน้าเวกเตอร์: ใช้ `titleBlockStrokes` ที่มีแล้ว (~0.2 วินาที/หน้า) แต่รันพร้อมกันหลาย worker + แคชรูปตัวอักษรของกรอบชื่อแบบ (กรอบเหมือนกันทุกหน้า ต่างแค่เลขแผ่น)
- หน้าสแกน: ตัดมุมจากภาพฝังความละเอียดจริง ไม่ย่อเหลือ 1000 px แบบตอนนี้ (บ้านประหยัด: ย่อแล้ว S-04 อ่านเป็น `5-04`)
- ผลของ P1 = แผนที่หน้า `{หน้า, รหัสแผ่น, ประเภท, ความมั่นใจ}` แสดงให้ผู้ใช้เห็นทันที (เห็นผลแรกใน ~2 วินาที)
- หน้าที่อ่านมุมไม่ออก → **อ่านตามปกติ** (ไม่ข้ามเพราะไม่แน่ใจ) และบอกผู้ใช้ว่าหน้าไหนระบบไม่แน่ใจ

**P2 อ่านข้อความ — เปลี่ยนจาก "OCR ทั้งหน้า" เป็น "อ่านรูปตัวอักษรครั้งเดียวต่อรูป"** (จุดที่ทำให้ถึง 10 วินาทีได้)
- หน้าเวกเตอร์: ตัวอักษร CAD ทุกตัวที่เหมือนกันวาดด้วยเส้นชุดเดียวกัน (หลักการที่ `glyphRead.ts` ใช้อยู่แล้ว) → แยกรูปตัวอักษรทั้งไฟล์, จัดกลุ่มรูปที่เหมือนกัน (ทั้งไฟล์มีราว 100–300 รูป), OCR เฉพาะตัวแทนของแต่ละกลุ่มในแผ่นรวมแผ่นเดียว, แล้วประกอบคำจากตำแหน่ง → งาน OCR ไม่โตตามจำนวนหน้า
  - วัดก่อนลงมือ: นับรูปไม่ซ้ำต่อไฟล์บน house_ready_1/2/4, dot32 (ไม่ต้อง OCR) ถ้า > 1,000 รูป แผนนี้ไม่คุ้ม
  - ความเสี่ยง: ตัวอักษรติดกัน, สระไทยบน/ล่าง → กลุ่มที่ไม่แน่ใจใช้ OCR ทั้งบรรทัดแบบเดิมเฉพาะบรรทัดนั้น
- หน้าสแกน: Paddle บน GPU อยู่แล้ว ส่วนที่ช้าคือเตรียมภาพบน main thread → ย้ายไป Web Worker (ผลเท่าเดิมทุกบิต) และให้เตรียมหน้าถัดไประหว่าง GPU อ่านหน้านี้ (ทำแล้ว T2)
- ภาษาไทย: แทน tesseract `tha+eng` (ตัวที่กิน CPU มากสุด) ด้วยโมเดล **Paddle ไทย `th_PP-OCRv5_mobile_rec`** (ไทย+อังกฤษ+ตัวเลข ~7.5 MB) บน onnxruntime-web ที่ใช้อยู่ — เปลี่ยนแค่ไฟล์โมเดลและพจนานุกรม · ต้องใช้คู่กับ det v5 · วัดกับด่าน OCR และ dot32 (ชุดไทยหนัก) ก่อนเก็บ

**P3 ประกอบ — ทะเบียนตำแหน่งจริง** (ข้อ 3 และ 4 ของผู้ใช้)
- ทุกชิ้นส่วนที่นับได้ต้องมี "ตำแหน่งจริง" หนึ่งเดียว = (ผังทางเลือก, ชั้น, ช่องกริด หรือพิกัดบนผัง) · มุมมองอื่น (รูปตัด, รูปด้าน, แบบขยาย, ผังซ้ำอีกทางเลือก) **ให้ข้อมูลคุณสมบัติได้ แต่เพิ่มจำนวนไม่ได้**
- แบบขยายเชื่อมกับผังด้วยเบอร์ (มีอยู่แล้วใน `sheetMerge`) + เก็บกรอบบนกระดาษทั้งสองฝั่งใน evidence (มีบางส่วนแล้ว) ให้ผู้ตรวจคลิกจากชิ้นส่วนไปหน้าผังและหน้าแบบขยายได้
- คำที่ OCR เจอซ้ำจากด้านแนวนอน/แนวตั้งหรือ tile ซ้อน: `dedupeWords` มีแล้ว · เพิ่มการตรวจ: ตำแหน่งเดียวกันที่มีสองเบอร์ → แจ้งผู้ตรวจ ไม่เลือกเอง

## งบเวลา 10 วินาที (ไฟล์เวกเตอร์ 64 หน้า, 10 หน้าโครงสร้าง)

| ขั้น | งบ | ทำอย่างไร |
|---|---|---|
| P0 | 1 วิ | มีแล้ว |
| P1 | 2 วิ | มุมกระดาษ 64 หน้า × 0.2 วิ ÷ 4–6 worker + แคชรูปกรอบชื่อแบบ |
| P2 | 6 วิ | อ่านรูปตัวอักษรไม่ซ้ำครั้งเดียว (ต้องวัดจำนวนรูปก่อน) |
| P3 | 1 วิ | มีแล้ว (`reader + merge` วัดได้ ~0.7 วิ) |

ไฟล์สแกนหลายหน้า: ตามความจริง GPU อ่าน ~5 วินาที/หน้า → 10 หน้าสแกน ≈ 50 วินาที ต่อให้เตรียมภาพเร็วแล้ว · 10 วินาทีสำหรับสแกนทำได้เฉพาะ "เห็นผลหน้าแรก" หรือเปิดซ้ำจากแคช

## ลำดับงาน (แต่ละข้อวัดก่อนเก็บ, ใช้ agy ลงมือ, ผมตรวจ diff)

1. **วัด:** นับรูปตัวอักษรไม่ซ้ำต่อไฟล์ (house_ready_1/2/4, dot32) — ตัดสินว่า P2 แบบ "อ่านรูปครั้งเดียว" ไปต่อหรือไม่ (ไม่แตะแอป)
2. **P1 แยกขั้นคัดหน้า:** อ่านมุมทุกหน้าก่อน OCR, พร้อมกันหลาย worker, ตัดมุมสแกนจากภาพความละเอียดจริง, ส่งแผนที่หน้าให้ UI · เกณฑ์: หน้าโครงสร้างใน manifest ของชุด dev ไม่ถูกข้ามสักหน้า
3. **UI สองโหมด:** โหมดเลือกเองใช้แผนที่หน้าจาก P1 เติมให้ PageSelector · โหมดอัตโนมัติแสดงหน้าที่ระบบเลือก/ข้าม พร้อมเหตุผล
4. **Paddle ไทย (spike):** แปลงโมเดล, ต่อเข้า paddleWorker เป็นตัวเลือก, วัดด่าน OCR + dot32 + เวลา
5. **ย้ายเตรียมภาพสแกนไป Worker**
6. **P2 อ่านรูปตัวอักษรครั้งเดียว** (ถ้าข้อ 1 คุ้ม) — ใหญ่สุด แบ่งเป็นงานย่อย
7. **P3 ทะเบียนตำแหน่ง:** ตรวจทุกที่ที่เพิ่มจำนวนชิ้นส่วน ให้มาจากผังที่เลือกเท่านั้น + ลิงก์ evidence สองฝั่ง
