## 1. Phase 1 — ตรวจหลักฐาน Round 16

### A1. ที่มาของเวลา "ทำมือ 80 นาที" — **[อ้างไว้ ไม่มีหลักฐาน]**
- ตัวเลขทั้ง 9 ขั้นตอนเป็น **ค่าคงที่พิมพ์ไว้ในสคริปต์** `tools/pilot/run_round16_validation.ts:280-295` แล้วเขียนลง xlsx — ไม่มีไฟล์บันทึกเวลาดิบ ไม่มีเวลาเริ่ม/จบ ไม่มีชื่อผู้ทำ (ระบุเพียง "Senior QS")
- ค่าทุกขั้นเป็นตัวเลขกลม (5, 15, 10, 8, 5, 12, 10, 10, 5) ซึ่งเข้ากับการประมาณมากกว่าการจับเวลา
- ขั้น "OCR & Schedule Extraction 15 นาที" ของงานมือ เป็นชื่อขั้นของซอฟต์แวร์ ไม่ใช่กิจกรรมของ QS ที่ทำมือ → โครงสร้างตารางออกแบบจากมุมของซอฟต์แวร์

### A2. ที่มาของเวลา "ใช้ระบบช่วย 14.1 นาที" — **[อ้างไว้ ไม่มีหลักฐาน]**
- พิมพ์ไว้ในสคริปต์เดียวกัน ขั้น 6 = 0.1 นาที อ้าง "5.7 ms" ซึ่งเป็นเวลาเครื่องคำนวณ ไม่ใช่เวลาคน
- ขั้น OCR 1.0 นาที ไม่สอดคล้องกับสภาพจริงที่ทราบ: OCR สแกนในเบราว์เซอร์ยังด้อยกว่าแคช (downsample 2400 px + แบ่ง 2 แถบ, R1 ยังทดสอบอยู่) และไม่มีการวัดเวลา OCR บนเบราว์เซอร์ในไฟล์ใด
- รายงานใช้คำว่า "per project sheet" ในข้อ 1.3 แต่ xlsx ใช้ "ต่อโครงการ" — หน่วยไม่ตรงกัน
- คำว่า "measured" / "Real-World QS Timing" ในรายงาน **ไม่ถูกต้อง**

### A3. จำนวนรอบการจับเวลา — **n = 1 (หรือ 0 ถ้านับเฉพาะการจับเวลาจริง)**
- มี 1 แถวต่อเงื่อนไข ไม่มีค่าเบี่ยงเบน ไม่มีผู้ทำคนที่สอง ไม่มีการสลับลำดับ (manual ก่อน/หลัง ทำให้เกิด learning effect)

### A4. ขอบเขตงานที่เปรียบเทียบ
- DPT House 1: 5 member groups, 14 ชิ้น (F01×2, C01×6, B01×1, B02×4, S01×1) [วัดแล้ว จาก xlsx]
- ไม่ครอบคลุมทั้งอาคาร (บ้านจริงมีคาน/พื้นชั้นบน, บันได, หลังคา คสล. ฯลฯ) → ไม่ใช่ "ทั้งโครงการ"
- ในชุดนี้ C01 และ S01 **ไม่ใช่ VERIFIED** (ESTIMATED / BOQ_REFERENCE)

### A5. รายการ VERIFIED 11 รายการ — **จำนวนถูก แต่ความเป็นอิสระไม่ได้พิสูจน์**
- 11 = ฐานราก 7 (H1-F01, H2-F01/F02/F03, DOT32-F01, CDC1-F01/F02) + คาน 4 (H1-B01, H1-B02, DOT32-GB01, GB02) [วัดแล้ว]
- **เสา VERIFIED = 0, พื้น VERIFIED = 0** — แต่ Round 16 ข้อ 8 อ้างว่า "Footings & Columns … 0 False Releases across all verified instances. Completely safe for assisted release" → **[ขัดแย้งกับหลักฐาน]** สำหรับเสา
- ผู้ตรวจในชุดข้อมูลระบุเพียง "Civil QS Reviewer" ไม่มีชื่อ ใบอนุญาต หรือลายมือชื่อ
- ฐานราก VERIFIED 7/7 ตรงกับระบบ **0.00% ทั้งไม้แบบและเหล็ก** (ถึงระดับ 0.01 กก.) — การถอดมืออิสระที่ใช้ของงอ/ระยะหุ้ม/น้ำหนักต่อเมตรของตัวเอง แทบเป็นไปไม่ได้ที่จะตรงทุกหลักใน 7/7 รายการ → บ่งชี้ว่าค่าอ้างอิงใช้ convention/สูตรเดียวกับเครื่อง ไม่ใช่อิสระ (ตัวอย่างหลักฐานตรง: H2-B01 หมายเหตุ "span assumed using engine formula parity")
- การอ้างอิงแผ่นแบบไม่ตรงกันข้ามไฟล์: H1-B01/B02 — ชุดข้อมูลอ้าง "S-07", failure register อ้าง "S-04", xlsx อ้าง "Page 30"

### A6. ความคลาดเคลื่อนรายชิ้น และ rebar P90 8.77% — **ตัวเลขคำนวณถูก แต่ไม่มีความหมายทางสถิติ**
- คำนวณซ้ำจาก xlsx ได้ค่าเดียวกัน [วัดแล้ว]: VERIFIED เหล็ก APE เรียง = {0×8, 0.04, 8.77, 10.39} → P90 (linear) = 8.77%
- P90 ที่ n = 11 คือ **ค่าของคาน B1 ตัวเดียว** ไม่ใช่การกระจายตัว
- MdAPE 0.00% เกิดจากฐานราก 7 ตัวที่ตรง 0% (ดู A5) ดึง median ลง — **ซ่อนความจริงว่าคาน VERIFIED มีเหล็ก MdAPE 4.41%, max 10.39%, ไม้แบบ max 25%** (ตาราง Phase 3)
- เครื่องหมายต่างกัน: B1 ระบบ **ต่ำกว่า** อ้างอิง 8.77% (เสี่ยงยื่นราคาต่ำ) ขณะ B2 **สูงกว่า** 10.39% — ค่าเฉลี่ยมีเครื่องหมาย (+0.40%) จึงหักล้างกันจนดูดี
- คำอธิบายสาเหตุ B1 ("อ้างอิงใช้ของงอยาวกว่า 12d") เป็นข้อสันนิษฐาน ไม่มีหลักฐานจากแผ่นแบบ

### A7. สาเหตุที่แท้จริงของ false release DPT-H1-S01 — **3 คำอธิบายขัดกันเอง; สาเหตุของ "การปล่อย" คือช่องโหว่ release gate**
| แหล่ง | คำอธิบาย | ตรวจสอบ |
|---|---|---|
| Failure register | อ้างอิงใช้ช่วงเต็ม, ระบบหักระยะหุ้ม | เลขในตารางเองได้ **15 เส้นทั้งสองแบบ** → ไม่อธิบายส่วนต่าง 2.55 กก. |
| xlsx หมายเหตุ | ช่วงเต็ม + ค่าเผื่อของงอ/เสีย | ไม่มีตัวเลขค่าเผื่อ ตรวจไม่ได้ |
| DECISIONS.md | input สังเคราะห์ไม่มี provenance → ความมั่นใจเริ่มต้น 95% | **ถูกส่วนที่เป็นกลไกการปล่อย** (ดู A8) |

- ข้อเท็จจริง [วัดแล้ว]: S01 ไม่มี provenance → flag `PROVENANCE_UNSPECIFIED` ระดับ **info** (−3) → ความมั่นใจ 95−3 = **92% ≥ 80** และไม่มี warn → **AUTO_RELEASE**
- ส่วนต่างปริมาณ 5.69% วัดเทียบ `BOQ_REFERENCE` ซึ่งยังไม่ได้พิสูจน์ — **ไม่ทราบว่าระบบหรือ BOQ ผิด** ปัญหาที่พิสูจน์ได้คือ "พื้นที่ไม่มีหลักฐานที่มาถูกปล่อยโดยไม่มีคนตรวจ"
- กลไกเดียวกันปล่อยฐานราก 7 + เสา 3 รายการที่ไม่มี provenance ด้วย — ที่ไม่เป็น false release เพียงเพราะค่าอ้างอิงบังเอิญตรง ไม่ใช่เพราะ gate ทำงาน

### A8. Fix เรื่อง UNKNOWN provenance อยู่ใน production path หรือไม่ — **ไม่อยู่ [ขัดแย้งกับหลักฐาน]**
- Round 16 ข้อ 7.1 อ้าง: "members lacking provenance cannot auto-release without human QS sign-off"
- โค้ดจริง `src/engine/qsEngine.ts:1048-1058`: ไม่มี provenance → flag ระดับ `info` เท่านั้น; `:1089` ความมั่นใจเริ่มต้น 0.95; `:1453` ต้องมี warn หรือ < 80% จึงเข้า NEEDS_REVIEW → **UNKNOWN ถูก AUTO_RELEASE**
- xlsx ของ Round 16 เองแสดง provenance = UNKNOWN ทั้ง 22 แถว และ 11 แถวเป็น AUTO_RELEASE ที่ 92% → หลักฐานของรอบเดียวกันหักล้างข้ออ้าง
- ไม่มีโหมด "commercial pilot" ใน `src/` (grep `pilot|commercialMode` ไม่พบ)
- `releaseGate.test.ts:28-46` ตรวจเพียง `provenanceLevel === 'UNKNOWN'` และมี flag — **ไม่ได้ assert ว่าสถานะไม่ใช่ AUTO_RELEASE**
- บรรเทาบางส่วน: เส้นทาง PDF → `sheetMerge.ts` ใส่ provenance ทุกครั้ง จึงพบ UNKNOWN น้อยในเส้นทางอัปโหลด PDF; ยังไม่ได้ตรวจว่าเส้นทางกรอกเอง/นำเข้า Excel สร้าง member โดยไม่มี provenance หรือไม่
- **ข้อสังเกตสำคัญ:** การที่ทั้ง 22 แถวเป็น UNKNOWN แปลว่า Round 16 **ไม่ได้ผ่านเส้นทางอ่านแบบจริงเลย** — เป็นการป้อนมิติที่พิมพ์ไว้เข้า `calculateMember` โดยตรง จึงวัดได้แค่ "เครื่องคิดเลข" ไม่ใช่ "การถอดแบบ" ซึ่งเป็นส่วนที่มีความผิดพลาดมากที่สุด (dev ถูก ~73%, held-out ถูก ~38% ตาม handoff)

## 2. Phase 2 — โปรโตคอลทดสอบแบบปิดตา

ดู `tools/pilot/ROUND17_BLIND_VALIDATION_PROTOCOL.md` สรุป:
- QS อิสระถอดแบบโดยไม่เห็นผล StructBOQ ใช้แบบชุดเดียวกัน (SHA-256) และ convention sheet ที่ตกลงล่วงหน้า
- แยกคอนกรีต / ไม้แบบ / เหล็ก (เหล็กแยกตามขนาด) เสมอ
- แยก `QS_CERTIFIED` ออกจาก `BOQ_REFERENCE` / `ESTIMATED` / `INVALID` เด็ดขาด
- บันทึกไฟล์แบบ, revision, หน้า, commit ของซอฟต์แวร์, ทุกการแก้ไขมือ
- ค่า StructBOQ ต้องมาจากเส้นทางผู้ใช้จริง (PDF → OCR → reader → engine)

**สถานะ: BLOCKED** — ไม่มีโครงการจริงใหม่ที่อยู่นอก `real_drawings/` และไม่มี QS อิสระที่ลงนามได้ รอบนี้ไม่มีการสร้างข้อมูลใด ๆ

| เสาที่ใช้ค่าสมมติแต่ AUTO_RELEASE | 3/3 | ไม่มี flag เพราะไม่มี provenance → ช่องโหว่เดียวกับ A8 |

### 3.2 รูปแบบรายงานสำหรับ blind pilot (ต้องใช้)
- ตารางต่อ ประเภท × หมวด ข้างต้น โดยใช้ `QS_CERTIFIED` เท่านั้น + คอลัมน์ `QS_ADJUDICATED` แยก
- เหล็กแยกขนาด (RB6/RB9/DB12/DB16/…) เพราะความผิดมักอยู่ที่เหล็กปลอก/เหล็กเสริมพิเศษ
- ภาคผนวกบังคับ: ตารางรายแถวทุก member group (ห้ามสรุปเฉพาะค่าเฉลี่ย)
- false release รายงานพร้อมขอบบน 95%
- manual-correction rate = จำนวนฟิลด์ที่ QS แก้ / จำนวนฟิลด์วิกฤตทั้งหมด แยกตามประเภท
- n < 10 ต่อช่อง → ห้ามรายงาน P90 เป็นตัวเลขเดี่ยว

## 4. Phase 4 — ผลิตภาพ (Productivity)

### 4.1 ความน่าเชื่อถือของ Round 16: **ต่ำมาก — ไม่ควรใช้อ้างอิง**
เหตุผล: n = 1, ค่าพิมพ์ในสคริปต์, ไม่มีบันทึกดิบ, ไม่มีผู้ทำที่ระบุตัวได้, ขั้นตอนอ้างอิงเวลาเครื่อง, ไม่รวมเวลา OCR เบราว์เซอร์จริง, ไม่รวมเวลาแก้ฟิลด์ที่ "ไม่พบ" (20–48%), ขอบเขต 14 ชิ้นไม่ใช่ทั้งอาคาร

### 4.2 แผนจับเวลาใหม่

**จุดเริ่ม/จบ (เหมือนกันทั้งสองแบบ):** เริ่ม = ได้รับไฟล์ PDF ชุดแบบ; จบ = QS ลงนามอนุมัติ BOQ โครงสร้าง (คอนกรีต/ไม้แบบ/เหล็ก) ตาม convention sheet

| ขั้น | ทำมือ | StructBOQ ช่วย |
|---|---|---|
| 1 | เปิดแบบ จัดหน้า | อัปโหลด + รอ OCR (จับเวลาเครื่องแยก) |
| 2 | อ่านตาราง/รูปตัด ลงมิติ | ตรวจผลอ่าน, กรอกฟิลด์ที่ไม่พบ |
| 3 | นับจำนวนจากผัง | ตรวจจำนวน/ช่วงคาน, ยืนยันขนาดเสารองรับ |
| 4 | คำนวณใน Excel | ตรวจรายการ NEEDS_REVIEW |
| 5 | ตรวจทานตัวเอง | ตรวจทานตัวเอง |
| 6 | ทำ ปร.4 | ส่งออก + ตรวจ ปร.4 |
| 7 | QS ลงนาม | QS ลงนาม |

**วิธีบันทึก:** แอปจับเวลาหรือบันทึกหน้าจอ timestamp ทุกขั้น (เริ่ม/หยุด/พัก), แยก "เวลาคนทำงาน" กับ "เวลารอเครื่อง", นับจำนวนการแก้ไขและข้อผิดพลาดที่พบตอนตรวจทาน

**การออกแบบการทดลอง:**
- ≥ 3 QS × ≥ 4 โครงการ (ต่างผู้ออกแบบ อย่างน้อย 2 โครงการเป็นแบบที่ระบบไม่เคยเห็น)
- crossover: QS แต่ละคนทำโครงการ X แบบมือ และโครงการ Y แบบช่วย สลับกันระหว่างคน — **ห้ามคนเดียวทำโครงการเดียวกันทั้งสองแบบ** (จำแบบได้ = learning effect)
- สุ่มลำดับ มือ/ช่วย
- รายงาน: มัธยฐานเวลาต่อโครงการและต่อ member group, ช่วงต่ำ–สูง, และ **คุณภาพควบคู่** (APE เทียบ `QS_CERTIFIED`) — เวลาที่ลดลงแต่ผิดมากขึ้นไม่นับเป็นการประหยัด
- ถ้า n รวม < 12 คู่ ให้รายงานเป็น "ผลเบื้องต้น" ห้ามอ้างเปอร์เซ็นต์ประหยัดเชิงพาณิชย์
