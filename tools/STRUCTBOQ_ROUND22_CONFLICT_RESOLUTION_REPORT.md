## สรุป
- **ข้อขัดแย้งแบบมีโครงสร้าง:** เดิมเป็นแค่ข้อความ ตอนนี้เป็น `FieldConflict` ที่ระบุ field และค่าของทุกแหล่ง พร้อมเลขหน้าต้นฉบับ อ้างอิง และวิธีอ่าน

- **Gate:** กันการปล่อยยอดทีละ field จนผู้ตรวจตัดสิน และการตัดสินต้องมีชื่อและเหตุผลตามระดับความเสี่ยง
- **Snapshot:** การตัดสินอยู่ใน snapshot จึงทำให้ approval เก่าหลุด
- **Excel:** มีแผ่นใหม่ "7.2 ค่าขัดแย้งระหว่างแหล่ง"

## 1. Architecture
```
แหล่งข้อมูล ─► ตรวจจับ (sourceConflicts.ts, pure)                      ─► provenance.fieldConflicts / fieldAgreements
  ├─ แบบขยายหลายแผ่นของเบอร์เดียว (sheetMerge: ทุก field ที่ชนิดชิ้นใช้)
  ├─ ชื่อฐานรากในผัง vs ความหนาในแบบขยาย (sheetMerge)
  ├─ แถวตาราง (schedule) เบอร์เดียวกันคนละหน้า (browserPipeline)
  └─ หมายเหตุทั่วไป vs ระยะหุ้มจากแบบขยายของชิ้น (qsEngine.memberConflicts — ต้องใช้สเปก)
                                   │
ผู้ตรวจตัดสิน (ConflictPanel) ─► member.conflictResolutions[] + ค่าใน field + fieldSources[field] = 'reviewer'
                                   │                     (อยู่บน member → อยู่ใน snapshot / fingerprint)
Gate (qsEngine.conflictStatuses) ─► FIELD_CONFLICT (warn, ระดับ field = คลาส B) จนกว่าจะ 'resolved'
                                   └► CONFLICT_RESOLVED (info) แสดงค่า หน้า ผู้ตรวจ เหตุผล
Excel 7.2 / ประวัติ (แผ่น 8) ◄── CalculatedQuantity.conflicts + reviewLog (TRACKED_FIELDS: conflictResolutions)
```
- **ที่เก็บข้อมูล:** ข้อขัดแย้งที่อ่านได้อยู่ใน provenance ส่วนการตัดสินอยู่บน member ที่อยู่ใน snapshot (provenance ไม่อยู่ใน snapshot ตามออกแบบ R20) การตัดสินจึงเปลี่ยน fingerprint
- **การจับคู่:** การตัดสินผูกกับ `conflictKey` = SHA-256 ของ field + (ค่า, หน้า, อ้างอิง) ของทุกแหล่ง ถ้าแหล่งเปลี่ยน (อ่านใหม่, revision ใหม่, หน้าเปลี่ยน) key จะต่าง และระบบถามใหม่

## 3. Conflict Detection Rules
| แหล่ง | field ที่เทียบ | หมายเหตุ |
|---|---|---|
| แบบขยาย/ตารางหลายแผ่นของเบอร์เดียว | ฐานราก: กว้าง, ยาว, หนา, เหล็กล่าง · คาน: กว้าง, ลึก, เหล็กบน, เหล็กล่าง, เหล็กปลอก · เสา: กว้าง, ลึก, เหล็กยืน, เหล็กปลอก · พื้น: หนา, เหล็กบน, เหล็กล่าง | เดิมเทียบแค่ "ก×ล×หนา" เป็นข้อความเดียว ไม่เทียบเหล็กเลย; เหล็กเทียบหลังทำให้อยู่รูปเดียวกัน (`2 - DB 12` = `2-DB12`) |
| ชื่อฐานรากในผัง (F0.90X0.90X0.30) vs ความหนาในแบบขยาย | หนา | Drawing note vs detail |
| แถวตารางเบอร์เดียวกันคนละหน้า | กว้าง, ลึก, ยาว, จำนวน, เหล็กบน/ล่าง/ปลอก | ทุกแถวยังเป็นชิ้นของตัวเอง (ปริมาณไม่เปลี่ยน) แต่ทุกแถวมีข้อขัดแย้งเดียวกัน |
| หมายเหตุทั่วไป (สเปก `coverSources = drawing_notes`) vs ระยะหุ้มจากแบบขยายของชิ้น (`fieldSources.cover = 'drawing'`) | ระยะหุ้ม | General notes vs detail; หมายเหตุไม่มีเลขหน้าในข้อมูลปัจจุบัน → "ไม่มีเลขหน้า" |

**การจัดประเภท:**
- **IDENTICAL:** ทุกแหล่งให้ค่าเดียวกัน
- **COMPLEMENTARY:** บางแหล่งไม่ให้ค่า ส่วนที่ให้ค่าตรงกัน
- **CONFLICT:** ค่าที่เทียบได้ต่างกันตั้งแต่ 2 ค่า
- **UNDECIDABLE:** มีค่าที่เขียนในรูปที่เทียบไม่ได้ (เช่น "ดูแบบขยาย") และต่างจากแหล่งอื่น

**ข้อห้ามที่บังคับใช้:**
- ไม่มีการโหวตเสียงข้างมาก (เทสต์: 2 หน้าเห็นตรงกัน 1 หน้าต่าง → ยัง CONFLICT)
- ไม่เลือกค่ามากหรือน้อยกว่า และไม่เลือกค่าล่าสุด
- ค่าที่ merge ใส่ใน field ระหว่างรอการตัดสินแสดงว่า "ชั่วคราว ยังไม่ตัดสิน" และอนุมัติปล่อยยอดไม่ได้

## 4. Resolution Workflow
- **ConflictPanel:** แสดงเฉพาะชิ้นที่มีข้อขัดแย้ง และแสดงทุกอย่างที่ผู้ตรวจต้องใช้:
  - field และสถานะ
  - ค่าปัจจุบัน (ชั่วคราว)
  - ตารางแหล่ง: ค่า, หน้าต้นฉบับ, อ้างอิงในแบบ, วิธีอ่าน
  - สถานะอนุมัติ
  - การตัดสินล่าสุด: ก่อน → หลัง, หน้า, ผู้ตรวจ, เวลา
- **ตัวเลือกของผู้ตรวจ:**
  - ยืนยันค่าแหล่งที่ 1, 2, … (กี่แหล่งก็ได้)
  - กรอกค่าที่ถูกต้อง
  - ส่งกลับตรวจสอบเพิ่มเติม (ยังไม่ปล่อยยอด)
- **ต้องมีชื่อผู้ตรวจทุกครั้ง** (ไม่มีชื่อ → ไปที่ช่องชื่อ)
- **เหตุผลตามความเสี่ยง** (`resolutionNeedsReason`):
  - บังคับเสมอเมื่อกรอกเองหรือส่งกลับ
  - บังคับเมื่อเลือกแหล่งของ field ความเสี่ยงสูง (กว้าง, ลึก/ยาว, หนา/สูง, จำนวน, เหล็กบน/ล่าง, ระยะหุ้ม)
  - ไม่บังคับเมื่อเลือกแหล่งของ field ความเสี่ยงกลาง (เหล็กปลอก)
- **ตัดสินทีละข้อ ไม่มี "ตัดสินทั้งหมด"** และไม่ใช้ร่วมกับตัวเลือก "ใช้กับเบอร์เดียวกัน"
- **สถานะ:** `open` (ยังไม่ตัดสิน) · `deferred` (ส่งกลับ) · `invalid` (ไม่มีชื่อหรือเหตุผล) · `mismatch` (ค่าใน field ถูกแก้หลังตัดสิน) · `resolved`

## 5. Provenance Changes
- `Provenance.fieldConflicts` และ `fieldAgreements` (ใหม่) บันทึกทุกแหล่งพร้อมหน้า
- **การตัดสิน:**
  - ตั้ง `fieldSources[field] = 'reviewer'` ไม่ใช่ `drawing` จึงไม่กลายเป็น Drawing-confirmed (เทสต์: `provenanceLevel ≠ DRAWING_VERIFIED`)
  - ค่าแหล่งที่ถูกเลือกถูกบันทึกเป็น "ผู้ตรวจเลือกตามหน้า X" ใน `CONFLICT_RESOLVED` และใน Excel
- **ข้อความเดิมที่ถูกแทน:**
  - "แบบขยายของ X ไม่ตรงกันระหว่างแผ่น" (เดิมทำให้ต้องยืนยันทุก field สำคัญ) → ข้อขัดแย้งราย field (ต้องตัดสินเฉพาะ field ที่ขัดแย้ง)
  - "ชื่อฐานราก … ไม่ตรงกับความหนา" → ข้อขัดแย้งราย field
  - field ที่ทุกแหล่งเห็นตรงกันไม่ต้องตัดสินซ้ำ
  - ข้อความ conflict แบบอื่น (เช่น ความยาวไม่ตรงกริด) ยังเป็น `CONFLICT` แบบเดิม

## 9. Remaining Risks และสถานะ
| ส่วน | สถานะ |
|---|---|
| ตรวจจับ: ข้อมูลเดียวกันหลายหน้า, ขนาด, จำนวนเหล็ก/ขนาดเหล็ก/ระยะเรียง (ผ่านการเทียบข้อความเหล็ก), จำนวนชิ้น (แถวตาราง) | **VERIFIED** (เทสต์ + เบราว์เซอร์สำหรับแถวตาราง) |
| แยก เหมือนกัน / เสริมกัน / ขัดแย้ง / ตัดสินไม่ได้ | **VERIFIED** (เทสต์) |
| Drawing note (ชื่อฐานราก) vs detail | **VERIFIED** (เทสต์) — ยังไม่ผ่านเบราว์เซอร์ |
| General notes vs detail (ระยะหุ้ม) | **PARTIALLY IMPLEMENTED** — ทำงานเมื่อ member มีระยะหุ้มจากแบบขยาย แต่ reader ปัจจุบันยังไม่อ่านระยะหุ้มรายชิ้นจาก PDF (มีแค่ DXF/ผู้ตรวจ); หมายเหตุไม่มีเลขหน้า |
| Drawing revision ใหม่ขัดแย้งกับข้อมูลเดิม | **NOT IMPLEMENTED** — ไม่มีการเทียบค่ากับ revision ก่อน; ความปลอดภัยมาจาก R20/R21 (hash ไฟล์อยู่ใน snapshot → approval เก่าหลุด; รีวิวผูกกับ hash จึงไม่ถูกกู้ไปใช้กับไฟล์ใหม่) |
| UI ตัดสินพร้อมทุกข้อมูล + ผู้ตรวจ + เหตุผลตามความเสี่ยง | **VERIFIED** (เบราว์เซอร์) |
| Approval safety (กัน, stale, ก่อน/หลัง, แหล่ง, ไม่ bulk, ไม่เป็น drawing-confirmed) | **VERIFIED** (เทสต์ + เบราว์เซอร์) |
| Excel 7.2 + ประวัติ | **VERIFIED** (เทสต์ + เบราว์เซอร์) |
| แหล่งเปลี่ยน → ตรวจใหม่ | **VERIFIED** ในเทสต์ / ยังไม่ผ่านเบราว์เซอร์ |

**ความเสี่ยงที่เหลือ**
- **แถวตาราง:** แถวเบอร์เดียวกันคนละหน้ายังเป็นหลายชิ้น ถ้าเป็นข้อมูลชุดเดียวกันที่พิมพ์ซ้ำ ปริมาณอาจนับซ้ำ (พฤติกรรมเดิม ไม่ได้เปลี่ยนเพื่อไม่แตะปริมาณ) ตอนนี้ค่าที่ขัดแย้งถูกกันไว้ แต่แถวที่เหมือนกันทุก field ไม่ถูกกัน (ได้แค่ IDENTICAL)
- **ข้อความเหล็กที่เขียนแปลก ๆ:** จะเป็น UNDECIDABLE ซึ่งปลอดภัย แต่ผู้ตรวจต้องตัดสินเพิ่ม
- **ค่าชั่วคราวระหว่างรอตัดสิน:** มาจากแผ่นที่ข้อมูลครบที่สุด ยอดชั่วคราวจึงอาจต่างจากค่าที่ตัดสินในภายหลัง (ไม่ปล่อยยอด)
- **ชื่อผู้ตรวจ:** ยังไม่ยืนยันตัวตน และ fingerprint ไม่มีลายเซ็น (จากรอบก่อน)
- **จำนวนข้อขัดแย้งในแบบจริง:** ยังไม่ได้วัด (`check:full` ผ่านและได้ผลเท่ารอบ 21 แต่รายงานของมันไม่บันทึกข้อขัดแย้ง)

**ภาพรวม:** **PARTIALLY IMPLEMENTED** — ส่วนหลักตรวจแล้ว ทั้งการตรวจจับ, การตัดสิน, gate, snapshot และ Excel ส่วนที่เหลือคือข้อขัดแย้งกับ revision เก่า (ยังไม่ทำ) และระยะหุ้มจากหมายเหตุ vs แบบขยายบน PDF จริง (ทำได้บางส่วน)
