## เฟส A — พร้อม deploy รุ่นทดลอง (ความเสี่ยงต่ำ ทำก่อน)

### A1 เลิกพึ่ง CDN ของ tesseract.js
- ตอนนี้ `T.createWorker(lang)` (`browserPipeline.ts` 343/370/385/398/622) โหลด worker, core wasm และ `*.traineddata` จาก CDN ค่าเริ่มต้น → เน็ต/CDN ล่ม = อ่านหน้าเวกเตอร์ไม่ได้
- ทำ: วางไฟล์ไว้กับแอป (`public/tesseract/`) แล้วส่ง `workerPath`, `corePath`, `langPath` ทุกจุดที่สร้าง worker (ทำ helper เดียว ใช้ทุกจุด)
- **ข้อมูลภาษาต้องเป็นไฟล์เดียวกับที่ CDN ส่งให้ตอนนี้** (ห้ามใช้ `eng.traineddata`/`tha.traineddata` ที่ราก repo โดยไม่ตรวจ — อาจคนละรุ่น) · ใส่ hash ของไฟล์ข้อมูลภาษาใน `currentOcrIdentity` (`scripts/gen_engine_identity.ts`) + เทสต์ใน `pageCache.test.ts`
- ตรวจ: เปิด 2 หน้าเวกเตอร์ในแอป (house_ready_4) เทียบคำกับรุ่น CDN ต้องเหมือนกันทุกคำ · ปิดเน็ตแล้วอ่านได้ · `npm test`

### A2 ขนาดของที่ deploy (รอผู้ใช้ตัดสิน)
- `dist` 187 MB: `public/datasets` 113 MB, `public/samples` 11 MB, PDF ที่ราก `public/` (house1.pdf, test_house6.pdf) ~19 MB
- ทางเลือก: (ก) ไม่ใส่ชุดข้อมูลใน build รุ่นจริง แสดงเฉพาะเมื่อมีไฟล์ (`datasets/index.json` ว่าง = ซ่อนรายการ) (ข) เก็บไว้แต่ย้ายไปโฮสต์แยก · ห้ามลบไฟล์ใน `public/` เอง

### A3 ที่ deploy (รอผู้ใช้: เลือกโฮสต์ + บัญชี + git remote)
- แอปเป็น static (`vite build`) · ไม่ต้องใช้ COOP/COEP (Paddle ตั้ง `numThreads = 1`) — ตรวจซ้ำหลัง build
- เพิ่มไฟล์ตั้งค่าโฮสต์ที่ผู้ใช้เลือก: cache ยาวสำหรับ `assets/*` (ชื่อมี hash), `.wasm`/`.onnx`/`.traineddata` ส่ง content-type ถูก
- ตรวจ: `npm run build && npx vite preview` แล้วรันเช็กลิสต์ A4 บน build นี้ ไม่ใช่ dev server

### A4 เช็กลิสต์ก่อนปล่อย (ทำบน build)
- ด่าน OCR ปัจจุบันเต็มรอบ (Paddle เปิดแล้ว) · check:full บนสำเนา · `npm test`
- เบราว์เซอร์: ไฟล์เวกเตอร์ (house_ready_4) · raster (house_ready_3) · สแกน (cdc_2) — console ไม่มี error, กดหยุดอ่านได้, เปิดซ้ำจาก cache, ป้ายกรอบเป็นชื่อชิ้นงาน, ส่งออก Excel ได้

- หน้าสแกน: เก็บ OCR จาก IndexedDB ของแอปแล้วรัน `check_boxes.ts` บนไฟล์นั้น (ภาพ "fl."/F2) — รายงานก่อนแก้

## เฟส B — เร็วขึ้นจริง (ทดลอง ต้องวัดก่อนเก็บ)

### B1 สปายก์: Paddle (WebGPU) อ่านป้ายหน้าเวกเตอร์แทน tesseract — วัดอย่างเดียว ยังไม่เปลี่ยนแอป
- เหตุผล: เวลาส่วนใหญ่คือ tesseract บนหน้าเวกเตอร์ · แอปมี Paddle + WebGPU อยู่แล้วสำหรับสแกน · ป้ายตัดได้จากเส้นเวกเตอร์ (`ocrLabels`) โดยไม่ต้องฝึกโมเดลตรวจจับ
- ทำ: ใน `scripts/offline_ocr.ts` เพิ่มโหมด env (เช่น `VECTOR_PADDLE=1`) ให้หน้าเวกเตอร์ใช้ Paddle อ่าน raster เดียวกัน (flat + turned) แทน tesseract · OCR ไปที่ scratchpad · ให้คะแนนด้วย `check_ocr_current.ts --from`
- วัด: ค่าถูก/ผิด/ไม่พบ 3 บ้าน เทียบ baseline · คำ ø, @, ภาษาไทย (`ป`, `มม.`) อ่านได้ไหม · เวลา Node ต่อหน้า (ใน Node เป็น WASM — ตัวเลขเร็วจริงต้องวัดในเบราว์เซอร์ WebGPU)
- **หยุดรายงาน** พร้อมตัวเลข · ไม่ผ่านเกณฑ์ความแม่นยำ = จบสปายก์ เก็บผลไว้ในเอกสาร
- ข้อควรรู้: โมเดล Paddle ที่ใช้เป็น `ch_PP-OCRv4` (จีน+ละติน) ไม่มีภาษาไทย → ข้อความไทยยังต้องใช้ tesseract `tha+eng`; ส่วนที่อาจได้ประโยชน์คือ engine `eng`

### B2 เร็วในความรู้สึก (ไม่แตะความแม่นยำ)
- เริ่ม OCR หน้าที่จำไว้ (หรือหน้าแรก ๆ) ทันทีหลังอัปโหลด ระหว่างผู้ใช้ยังเลือกหน้า · แสดงผลอ่านทีละหน้าเมื่อเสร็จ
- เกณฑ์: เวลาจนเห็นผลหน้าแรก ≤ 10 วินาที (วัดในเบราว์เซอร์) · ผลอ่านทั้งไฟล์ต้องเท่าเดิมทุกคำ
