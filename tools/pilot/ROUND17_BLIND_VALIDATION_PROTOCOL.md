# StructBOQ Round 17 — โปรโตคอลการทดสอบแบบปิดตา (Blind Project Validation Protocol)

**วันที่:** 2026-11-03
**สถานะ:** โปรโตคอลเท่านั้น — **BLOCKED BY MISSING DATA** (ยังไม่มีโครงการจริงใหม่ที่ไม่อยู่ในชุดข้อมูลเดิม และยังไม่มี QS อิสระที่ลงนามได้)
**ข้อห้าม:** เอกสารนี้ไม่มีตัวเลขผลลัพธ์ใด ๆ ทุกช่องผลลัพธ์ต้องว่างจนกว่าจะเก็บข้อมูลจริง

---

## 1. เงื่อนไขก่อนเริ่ม (Entry criteria) — ต้องครบทุกข้อ

| # | เงื่อนไข | หลักฐานที่ต้องเก็บ |
|---|---|---|
| E1 | โครงการไม่อยู่ใน `real_drawings/*` ใด ๆ (dev หรือ held-out) และไม่เคยถูกใช้จูนกฎการอ่าน | ชื่อโครงการ, SHA-256 ของไฟล์ PDF ทุกไฟล์, เทียบกับรายการไฟล์ใน `real_drawings/` |
| E2 | มีแบบโครงสร้างครบชุด (ผัง ฐานราก เสา คาน พื้น ตารางเหล็ก รายการประกอบแบบ) | รายการแผ่น + เลขแผ่น + revision ทุกแผ่น |
| E3 | มี QS อิสระอย่างน้อย 1 คน (แนะนำ 2 คน) ที่ไม่เคยเห็นผล StructBOQ ของโครงการนี้ | ชื่อ, คุณวุฒิ/ใบอนุญาต (ถ้ามี), ประสบการณ์ปี, ลายมือชื่อยินยอมเงื่อนไขปิดตา |
| E4 | ตกลงเกณฑ์การวัดปริมาณ (measurement convention) เป็นลายลักษณ์อักษรก่อนเริ่ม | เอกสาร convention ฉบับเดียว ใช้ทั้ง QS และ StructBOQ (ดูข้อ 4) |
| E5 | มีผู้ดูแลข้อมูล (data custodian) ที่ไม่ใช่ QS และไม่ใช่ผู้รัน StructBOQ | ชื่อ + บันทึกการส่งมอบไฟล์ |
| E6 | ล็อกเวอร์ชันซอฟต์แวร์ก่อนรัน | git commit hash ของ StructBOQ (ต้อง commit ก่อน — ปัจจุบันมีไฟล์ค้าง uncommitted จำนวนมาก) |

ถ้าข้อใดไม่ครบ → สถานะ **BLOCKED** ห้ามรายงานผล

## 2. การแยกทีมและการปิดตา

```
              ┌──────────────── Data custodian ────────────────┐
              │  รับ PDF ต้นฉบับ → hash → แจกสำเนาเดียวกันให้ 2 ฝั่ง │
              └────────────┬───────────────────────┬───────────┘
                           │                       │
          ┌────────────────▼───────┐   ┌───────────▼────────────────┐
          │ ทีม A: QS อิสระ (มือ)    │   │ ทีม B: ผู้ใช้ StructBOQ       │
          │ ไม่เห็นผล StructBOQ       │   │ ไม่เห็นผลของ QS             │
          │ ส่งผลแบบปิดผนึก (hash)    │   │ ส่งผลแบบปิดผนึก (hash)      │
          └────────────────┬───────┘   └───────────┬────────────────┘
                           └──────────┬────────────┘
                         เปิดผนึกพร้อมกันโดย custodian → เปรียบเทียบ
```

- ทีม A และ B ห้ามสื่อสารเรื่องปริมาณจนกว่าจะเปิดผนึก
- ผลแต่ละฝั่งส่งเป็นไฟล์ + SHA-256 บันทึกเวลาส่ง ก่อนเปิดผนึก
- หลังเปิดผนึก **ห้ามแก้ไขผลของทั้งสองฝั่ง** การแก้ไขใด ๆ เป็นรอบ "adjudication" แยก (ข้อ 6) และบันทึกเป็นแถวใหม่ ไม่ทับแถวเดิม
- ทีม B ต้องบันทึกทุกการแก้ไขค่าด้วยมือใน StructBOQ (ฟิลด์, ค่าเดิม, ค่าใหม่, เหตุผล, หน้าแบบ) — ใช้คำนวณ manual-correction rate

## 3. ขอบเขตการวัด

- ทุกองค์อาคารที่มีในแบบ: ฐานราก, เสาเข็ม (ถ้ามี — ระบุว่าอยู่นอกขอบเขต StructBOQ หรือไม่), เสา, คาน, พื้น, บันได, ผนัง คสล.
- แยก 3 หมวดงานเสมอ **ห้ามรวมเป็นยอดเงินเดียว**:
  1. คอนกรีต (ม³) — แยกตามกำลังอัด/ชั้นคอนกรีตถ้าแบบระบุ
  2. ไม้แบบ (ม²)
  3. เหล็กเสริม (กก.) — แยกตามขนาด (RB6, RB9, DB12, …) และแยก น้ำหนักสุทธิ / ของงอ / ทาบ / เผื่อเสีย
- หน่วยเปรียบเทียบ: **ระดับกลุ่มองค์อาคาร (member group, เช่น B2 ทุกตัว)** และ **ระดับโครงการ** ทั้งสองระดับ
- คอนกรีตหยาบ, ทราย, ดินขุด: บันทึกแยก ไม่นับในเกณฑ์ผ่าน/ไม่ผ่านของรอบนี้

## 4. เกณฑ์การวัดปริมาณที่ต้องตกลงก่อน (Convention sheet)

ต้องระบุทุกข้อก่อนเริ่ม และทั้ง QS กับ StructBOQ ใช้ชุดเดียวกัน:

| หัวข้อ | ตัวเลือกที่ต้องเลือก 1 ข้อ |
|---|---|
| ไม้แบบข้างคาน | เต็มความลึก (gross) / หักความหนาพื้น (slab-deducted) |
| ความยาวคาน | ศูนย์กลางเสา–ศูนย์กลางเสา / ระยะช่องว่างสุทธิ (clear span) |
| จุดตัดคาน–เสา คอนกรีต | นับในเสา / นับในคาน |
| ความสูงเสา | จากหลังฐานราก–ใต้คาน / ถึงหลังคาน |
| จำนวนเหล็กพื้น | ช่วงสุทธิหักระยะหุ้ม / ช่วงเต็ม |
| ของงอ | 90° / 135° / ตามรายการประกอบแบบ; ความยาวของงอ (เช่น 12d) |
| ระยะทาบ | ตามรายการประกอบแบบ / ค่ามาตรฐาน (ระบุค่า) |
| ความยาวเหล็กต่อเส้น | 10 ม. / 12 ม. / ไม่คิดเศษตัด |
| % เผื่อเสีย | ระบุตัวเลข หรือ "ไม่รวม" (แนะนำ: เปรียบเทียบที่ "ไม่รวม") |
| น้ำหนักเหล็กต่อเมตร | ตาราง มอก. ฉบับที่ใช้ |

ข้อขัดแย้งที่เกิดจาก convention ต่างกัน **ไม่ใช่ข้อแก้ตัวหลังเห็นผล** — ถ้าตกลงไว้แล้วแต่ฝั่งใดใช้ต่างไป ให้นับเป็นความคลาดเคลื่อนของฝั่งนั้น

## 5. ชั้นของข้อมูลอ้างอิง (แยกเด็ดขาด)

| ชั้น | นิยาม | ใช้วัดความแม่นยำ? |
|---|---|---|
| `QS_CERTIFIED` | ถอดโดย QS อิสระภายใต้ข้อ 2 และลงนามรับรองรายแถว | **ใช่ — เป็นค่าจริงหลักชั้นเดียว** |
| `QS_ADJUDICATED` | ค่าหลังรอบ adjudication (ข้อ 6) ลงนามโดย QS คนที่สาม | ใช่ — รายงานแยกคอลัมน์ ไม่ทับ `QS_CERTIFIED` |
| `BOQ_REFERENCE` | BOQ ของผู้ออกแบบ/ราชการ (ปร.4/ปร.5) | **ไม่ใช่** — รายงานแยก เพื่อดูความต่างกับเอกสารประกวดราคาเท่านั้น |
| `ESTIMATED` | ค่าที่มีสมมติฐาน (ช่วง/ความสูง/จำนวน) ที่แบบไม่ได้ให้ | ไม่ใช่ — รายงานแยก |
| `INVALID` | แบบไม่ครบ/ถูกตัด อ่านไม่ได้ | ไม่ใช่ — นับเป็น invalid-input rate |

ห้ามสร้างค่าอ้างอิงโดยรัน `qsEngine.ts` หรือสูตรเดียวกับ StructBOQ (บทเรียนจาก Round 16: ค่าอ้างอิงบางรายการระบุว่า "assumed using engine formula parity")

## 6. Adjudication (หลังเปิดผนึก)

1. รายการที่ APE เกินเกณฑ์ (คอนกรีต > 2%, ไม้แบบ > 5%, เหล็ก > 5% ต่อกลุ่ม) ส่งให้ QS คนที่สาม
2. QS คนที่สามจัดประเภทสาเหตุตาม taxonomy 10 ข้อของ Round 16 และระบุว่า "ฝั่งไหนผิด / ทั้งคู่ / convention ไม่ชัด"
3. บันทึกเป็นแถวใหม่ ห้ามแก้ `QS_CERTIFIED` หรือผล StructBOQ เดิม
4. ห้ามแก้กฎการอ่านหรือสูตรระหว่างรอบ — โครงการนี้กลายเป็น held-out ถาวรหลังเปิดผนึก

## 7. บันทึกต่อรายการ (ต่อ member group)

`project_id, drawing_file, drawing_sha256, sheet_no, sheet_revision, revision_date, member_tag, member_type, count, width, depth, length/height, top_bar, bottom_bar, stirrup, convention_ref, qs_concrete, qs_formwork, qs_rebar_by_dia, qs_signed_by, qs_signed_at, sb_commit, sb_concrete, sb_formwork, sb_rebar_by_dia, sb_status (AUTO_RELEASE/NEEDS_REVIEW/REJECTED), sb_provenance_level, sb_confidence, sb_flags, sb_manual_edits(n), sb_input_invalid(Y/N), gt_tier, adjudicated_value, adjudication_cause`

- ทุกค่า StructBOQ ต้องมาจาก **เส้นทางจริงของผู้ใช้** (อัปโหลด PDF → OCR → reader → engine) ไม่ใช่การพิมพ์ member เข้า `calculateMember` โดยตรง — ถ้าต้องพิมพ์เอง ให้บันทึกเป็น manual edit
- ห้ามรัน `FULL_BOQ=1 npm run check:full` ในที่ (ทับ baseline) — ถ้าจะรันให้รันบนสำเนาใน scratchpad

## 8. ตัวชี้วัดที่ต้องรายงาน

ดูรายละเอียดใน `tools/STRUCTBOQ_ROUND17_BLIND_VALIDATION.md` หัวข้อ Phase 3 — สรุป: ต่อ **ประเภทโครงสร้าง × หมวดงาน**: n, MdAPE, P90 APE, Max APE, mean signed error (%), false-release count, NEEDS_REVIEW rate, invalid-input rate, manual-correction rate และ **ตารางรายแถวทุกกลุ่ม** แนบท้ายเสมอ

## 9. ขนาดตัวอย่างขั้นต่ำ

- ต่อประเภทองค์อาคาร (ฐานราก/เสา/คาน/พื้น): **≥ 20 member groups จาก ≥ 3 โครงการที่ต่างผู้ออกแบบ** ก่อนจะรายงาน P90 เป็นตัวเลขที่มีความหมาย (n < 10 ให้รายงาน P90 ว่า "n น้อยเกินไป" และแสดงรายแถวแทน)
- false release: ถ้าพบ 0 จาก n รายการ ให้รายงานขอบบน 95% ≈ 3/n (rule of three) ไม่ใช่ "0%"

## 10. เงื่อนไขหยุด (Stop rules)

- พบ false release ที่ทำให้ปริมาณเหล็กของโครงการคลาดเกิน 5% → หยุดและรายงานทันที
- พบว่าทีมใดเห็นผลอีกฝั่งก่อนเปิดผนึก → ผลรอบนั้นเป็นโมฆะ บันทึกเหตุผล
- พบว่าโครงการเคยอยู่ในชุด dev/held-out → โมฆะ

## 11. สถานะปัจจุบัน

| รายการ | สถานะ |
|---|---|
| โครงการจริงใหม่ | **ไม่มี — BLOCKED** |
| QS อิสระที่ลงนามได้ | **ไม่มี — BLOCKED** (ชุดข้อมูลเดิมระบุผู้ตรวจเพียง "Civil QS Reviewer" ไม่มีชื่อ/ลายมือชื่อ) |
| Convention sheet | ร่างได้ (ข้อ 4) รอผู้ใช้/QS เลือก |
| Commit ล็อกเวอร์ชัน | ยังไม่มี (ไฟล์ค้าง uncommitted, ห้าม commit โดยไม่ได้รับคำสั่ง) |
