# StructBOQ Round 17 — ความพร้อมเชิงพาณิชย์ (Commercial Readiness)

**วันที่:** 2026-11-03
**หลักการ:** แยก "วัดแล้ว" ออกจาก "ประมาณการ/สมมติฐาน" ทุกข้อ ไม่มีตัวเลขรายได้หรือขนาดตลาดที่ไม่มีแหล่งอ้างอิง — ช่องที่ไม่มีข้อมูลเขียนว่า **ไม่มีข้อมูล**

ป้ายกำกับที่ใช้: **[วัดแล้ว]** = มีหลักฐานในไฟล์ที่ตรวจได้ · **[สมมติฐาน]** = ต้องพิสูจน์ · **[ไม่มีข้อมูล]**

---

## 1. กลุ่มลูกค้าเป้าหมาย [สมมติฐาน — ยังไม่มีการสัมภาษณ์ลูกค้าแม้แต่รายเดียว]

| กลุ่ม | ทำไมอาจเหมาะ | ข้อกังวล |
|---|---|---|
| ผู้รับเหมาขนาดเล็ก–กลางที่ประมูลงานราชการ (อาคารแบบมาตรฐาน เช่น ศพด., บ้านพักแบบ DPT, ศาลา) | ชุดข้อมูลปัจจุบันทั้งหมดเป็นแบบมาตรฐานราชการไทย; ต้องถอด BOQ แข่งกับเวลาก่อนยื่นซอง | ถ้าใช้แบบมาตรฐานซ้ำ ผู้รับเหมาอาจมี BOQ เก่าอยู่แล้ว → ปัญหาเล็กลง |
| วิศวกร/QS อิสระที่รับถอดแบบเป็นงาน | ลดเวลางานซ้ำ ๆ (ฐานราก/เสา) | ความรับผิดต่อปริมาณผิดตกที่ QS คนนั้นโดยตรง → ต้องตรวจทุกบรรทัดอยู่ดี |
| อปท./หน่วยงานที่ต้องตรวจ ปร.4 ของผู้ออกแบบ | ใช้เป็นเครื่องมือตรวจซ้ำ (second check) ไม่ใช่ทำแทน | กระบวนการจัดซื้อ/งบประมาณซอฟต์แวร์ภาครัฐ [ไม่มีข้อมูล] |

**ไม่แนะนำ** ในขั้นนี้: โครงการเอกชนขนาดใหญ่, อาคารสูง, งานที่ใช้ BBS สั่งตัดเหล็กจริง (ระบบเองห้ามใช้ BBS สั่งตัด)

## 2. ปัญหาจริงที่แก้

- **แก้ได้ (บางส่วน) [วัดแล้ว ระดับ calculator]:** เมื่อได้มิติ+เหล็กถูกต้องแล้ว การคำนวณปริมาณคอนกรีต/ไม้แบบ/เหล็กของฐานรากตรงกับค่าอ้างอิงใน Round 16 — แต่ค่าอ้างอิงยังไม่ได้พิสูจน์ความเป็นอิสระ (ดูรายงานหลัก A3)
- **ยังไม่ได้พิสูจน์ [ไม่มีข้อมูล]:** ส่วนที่กินเวลาจริงของ QS คือ "อ่านแบบ" ไม่ใช่ "คูณเลข" — ความแม่นยำการอ่านแบบวัดล่าสุด (ตาม handoff 2026-10-29, OCR แคช): dev ถูก ~73% / ผิด ~7% / ไม่พบ ~20%; held-out ถูก ~38% / ผิด ~14% / ไม่พบ ~48%; และ BOQ dot32 ในเบราว์เซอร์ MAPE ~54% → ส่วนที่มีมูลค่ามากที่สุดยังไม่พร้อม
- **ความเสี่ยงซ่อน:** ผิด ~7–14% ของฟิลด์ที่อ่าน "ผิดแบบมั่นใจ" แย่กว่า "ไม่พบ" เพราะ QS อาจไม่สังเกต

## 6. รูปแบบรายได้ที่เป็นไปได้ [สมมติฐานทั้งหมด — ไม่มีตัวเลขราคา/รายได้เพราะไม่มีแหล่งข้อมูล]

1. **ต่อโครงการ (pay-per-project)** — สอดคล้องกับงานประมูลที่มาเป็นครั้ง ๆ
2. **สมาชิกรายเดือน/ปีต่อผู้ใช้** — เหมาะกับ QS ที่ถอดแบบต่อเนื่อง
3. **บริการถอดแบบ + ตรวจโดย QS (service-assisted)** — ขายผลลัพธ์ที่ QS ลงนามแล้ว ไม่ใช่ขายซอฟต์แวร์; ลดความเสี่ยงความรับผิดของลูกค้า แต่ต้นทุนแรงงานสูง
4. **ไลเซนส์ให้หน่วยงานตรวจ ปร.4** — ใช้เป็นเครื่องมือตรวจซ้ำ

ทุกข้อต้องการข้อมูลที่ยังไม่มี: ความเต็มใจจ่าย, จำนวนโครงการ/ปีของลูกค้า, ราคาคู่แข่ง — **ต้องสัมภาษณ์ลูกค้าอย่างน้อย 10 รายก่อนกำหนดราคา**

## 7. ทำไม QS หรือบริษัทอาจไม่เปลี่ยนมาใช้

1. **ความเชื่อใจ:** QS ลงนามรับผิดชอบ — ถ้าต้องตรวจทุกบรรทัดอยู่แล้ว เวลาประหยัดอาจน้อย
2. **ความแม่นยำการอ่านแบบยังต่ำบนแบบที่ไม่เคยเห็น** (held-out ถูก ~38%)
3. **Convention ไม่ตรงสัญญา:** ไม้แบบ gross vs หักพื้น, ช่วงคานศูนย์กลาง vs สุทธิ — ถ้าเลือกไม่ได้ในระบบ ผลต้องแก้มือ
4. **เครื่องมือเดิมพอใช้:** Excel template ของบริษัท + BOQ แบบมาตรฐานที่มีอยู่แล้ว
5. **ขอบเขตแคบ:** ปล่อยอัตโนมัติได้เฉพาะฐานราก (และเสา — ซึ่งยังไม่มีค่าอ้างอิง VERIFIED เลย)
6. **ข้อมูลการทำงาน/ความลับแบบ:** แม้รันในเบราว์เซอร์ ลูกค้าอาจกังวลโหมด AI ที่ส่งภาพไปบริการภายนอก
7. **ไม่มีกรณีอ้างอิง (reference customer)** ที่ใช้จริงแล้วบอกต่อได้

## 8. สรุปความพร้อมเชิงพาณิชย์

| มิติ | สถานะ |
|---|---|
| ปัญหา/ลูกค้า | สมมติฐาน — ยังไม่ได้สัมภาษณ์ |
| เวลาประหยัด | ไม่มีข้อมูลที่วัดจริง |
| ความแม่นยำบนแบบใหม่ | ยังไม่ได้ทดสอบแบบปิดตา |
| ความปลอดภัยการปล่อยผล | มีช่องโหว่ UNKNOWN provenance |
| รายได้ | ไม่มีข้อมูล |

**ข้อสรุป:** ยังไม่พร้อมขายเชิงพาณิชย์ ขั้นถัดไปที่คุ้มที่สุดคือ (1) ปิดช่องโหว่ release gate (ต้องได้รับอนุมัติก่อนแก้โค้ด) (2) blind pilot 1 โครงการตามโปรโตคอล (3) สัมภาษณ์ลูกค้าเป้าหมาย พร้อมวัดเวลาจริง
