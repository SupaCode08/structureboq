## 1. Architecture

### Trace ก่อนแก้ (ส่วนที่ใช้แยกชิ้นในแต่ละขั้น)
| ขั้น | ตัวแยกชิ้น | ปัญหา |
|---|---|---|
| Schedule row → `ExtractedMember` (`scheduleMembersFromPage`) | หนึ่งแถว = หนึ่ง member; `tag` = เบอร์; `count` จากแถว; `gridLocation = Sheet-P{หน้า}` (ไม่ใช่ตำแหน่ง); evidence = หน้าและ bbox | แถวเดียวกันที่พิมพ์ซ้ำคนละหน้า = 2 member |
| Plan → `ExtractedMember` (`mergeSheetReadings`) | หนึ่งเครื่องหมายในผัง = หนึ่ง member (tag + ชั้น + กริด) และใช้แบบขยายเป็น spec ผ่าน tag | — |
| `ExtractedMember` → `CalculatedQuantity` (`computeProject`) | index ของ member → `itemId` (`QS-F-001`…); กฎซ้ำเดิม: ชั้น + กริด + tag เดียวกัน → REJECTED + ปริมาณ 0 (ยกเว้นกริด `-` / `Sheet-P*`) | แถวตาราง (`Sheet-P*`) ไม่ถูกตรวจเลย; แถวตารางกับชิ้นในผังเบอร์เดียวกันไม่ถูกตรวจ |
| BOQ / Excel / เทียบ BOQ | รวมทุกรายการที่ไม่ใช่ REJECTED | นับซ้ำได้ |

### หลังแก้
```
members ─► detectDuplicateGroups (กลุ่มตาม type + tag; จำแนก + หลักฐาน; หาคำตัดสินที่ key ตรง)
                │
computeProject ─┤ กลุ่มที่ยังไม่ตัดสิน → DUPLICATE_RISK (warn) + NEEDS_REVIEW ทุกแหล่ง (approval ไม่ปล่อยยอด)
                ├ SAME_INSTANCE (ผู้ตรวจ) → นับที่แหล่งแรก; แหล่งอื่น REJECTED + zeroOut + linkedTo
                └ DISTINCT (ผู้ตรวจ) → นับทุกแหล่ง (DUPLICATE_RESOLVED info)
                ▼
ยอดรวม / BOQ / Excel 7.3 / ประวัติ (แผ่น 8)
```
- gate อยู่ใน `computeProject` เพราะต้องเห็นทุก member ทุกทางที่สร้างยอดรวมผ่านจุดนี้ ได้แก่ App, Excel, เทียบ BOQ, benchmark และ scripts
- `calculateMember` เดี่ยว ๆ ถูกใช้ที่ ManualCalculator (ชิ้นเดียว) และ `approvalFor` (ยอด snapshot) ซึ่งไม่ได้สร้างยอดรวม

## 3. Entity Model
| แนวคิด | ในระบบ |
|---|---|
| Member Type | `memberType` (FOOTING, BEAM, …) |
| Member Reference | `tag` (F2, GB3) — จับกลุ่มด้วย type + tag ตัวพิมพ์ใหญ่ |
| Source Occurrence | หนึ่ง `ExtractedMember` = หนึ่งการปรากฏ (หน้า, ตำแหน่ง, ข้อความ, ค่า) — `occurrenceOf()` |
| Physical Instance | `instanceId`: มีตำแหน่ง → `F2@Story 1 / A/1`, ไม่มีตำแหน่ง → `F2@p2#1`; แหล่งที่ลิงก์แล้วใช้ id ของแหล่งแรก; `count` ของแถว = จำนวนชิ้นจริงที่แหล่งนั้นแทน |
| Duplicate Reference | กลุ่มที่ผู้ตรวจยืนยัน `SAME_INSTANCE` |
| Repeated Specification | `SAME_SPECIFICATION` (ต่างเบอร์ ค่าเหมือนกัน) — แสดงอย่างเดียว ไม่จับรวม ไม่กันยอด |

**กฎสำคัญ:**
- เบอร์เดียวกันไม่ได้แปลว่าเป็นชิ้นเดียวกันโดยอัตโนมัติ
- ค่าเหมือนกันไม่ได้แปลว่าเป็นชิ้นเดียวกัน
- หลักฐานว่าเป็นชิ้นเดียวกันมีแค่ตำแหน่งเดียวกัน (ชั้น + กริด) หรือคำตัดสินของผู้ตรวจ

## 4. Duplicate Detection Rules (ต่อกลุ่มเบอร์เดียวกัน ≥ 2 แหล่ง)
| เงื่อนไข | การจำแนก | กันยอด? | หลักฐานที่บันทึก |
|---|---|---|---|
| ทุกแหล่งมีตำแหน่ง และไม่ซ้ำกัน | DISTINCT_PHYSICAL_INSTANCES | ไม่ | ตำแหน่งทั้งหมด |
| ทุกแหล่งมีตำแหน่ง และมีตำแหน่งซ้ำ | SAME_PHYSICAL_INSTANCE | ไม่ (กฎตำแหน่งซ้ำเดิมนับครั้งเดียว) | ชั้นและกริดเดียวกัน |
| ค่าต่างกัน (ไม่ครบตำแหน่ง) | CONFLICTING_SPECIFICATION | กัน | ค่าของแต่ละแหล่ง |
| ไม่มีตำแหน่งทุกแหล่ง ค่าเหมือนกัน | POSSIBLE_DUPLICATE | กัน | "ค่าเหมือนกันทุก field คนละหน้า (2, 4)…" หรือ "หน้าเดียวกัน ข้อความเดียวกัน — อาจอ่านแถวเดิมซ้ำ" |
| มีทั้งแหล่งที่มีตำแหน่งและไม่มีตำแหน่ง (ผัง + ตาราง/แบบขยาย) | INSUFFICIENT_EVIDENCE | กัน | จำนวนแหล่งแต่ละแบบ |
| ต่างเบอร์ ค่าเหมือนกัน ไม่มีตำแหน่ง | SAME_SPECIFICATION | ไม่ | "ไม่ใช่หลักฐานว่าเป็นชิ้นเดียวกัน" |

**กรณีในโจทย์ที่ไม่ได้ทำเป็นกฎแยก**
- **PDF + DXF:** แอปเปิดได้ทีละไฟล์ และสองแหล่งนี้ไม่เคยรวมในโครงการเดียวกัน จึงไม่มีทางเกิดใน flow ปัจจุบัน — **NOT IMPLEMENTED (ไม่มีทางเข้า)**
- **ข้อมูลที่ Sheet Merge แสดงซ้ำ:** merge สร้าง member จากเครื่องหมายในผังเท่านั้น และใช้แบบขยายเป็น spec ไม่ใช่ member กรณีเครื่องหมายเดียวกันซ้อนที่ตำแหน่งเดียวกันเข้ากฎ SAME_PHYSICAL_INSTANCE

## 5. Physical Instance Linking
**ตัวเลือกของผู้ตรวจ (ตัดสินทีละกลุ่ม ไม่มี bulk ข้ามกลุ่ม)**
- ยืนยันว่าเป็นชิ้นงานเดียวกัน
- ยืนยันว่าเป็นคนละชิ้น
- ส่งกลับตรวจสอบ
- ยังตัดสินไม่ได้

**ทุกคำตัดสินต้องมีชื่อผู้ตรวจและเหตุผล** เพราะทั้งการลดยอดและการยืนยันว่านับครบเป็นความเสี่ยงสูง และระบบประทับเวลาให้

**ลิงก์ (SAME_INSTANCE) จะถูกปฏิเสธเมื่อ**
- ค่าของแต่ละแหล่งต่างกัน (ต้องตัดสินค่าขัดแย้ง R22 ก่อน)
- แหล่งอยู่คนละตำแหน่งในผัง

**การบันทึกและการจับคู่**
- คำตัดสินบันทึกบนทุกแหล่งในกลุ่ม และผูกกับ `duplicateGroupKey` = SHA-256 ของ (type, tag, หน้า, ตำแหน่ง, ข้อความ, ค่า) ของทุกแหล่ง
- ถ้าแหล่งเปลี่ยน (หน้า, ค่า, มีแหล่งเพิ่ม) ระบบถามใหม่ และคำตัดสินเดิมไม่ถูกใช้

**ผลของการลิงก์**
- แหล่งแรก (index ต่ำสุด) ถูกนับ ส่วนแหล่งอื่นเป็น REJECTED และปริมาณ 0 พร้อมข้อความ "แหล่งซ้ำของชิ้นเดียวกับ QS-F-001 (ผู้ตรวจยืนยัน) — ไม่นับซ้ำ"
- ไม่มีการลบ member: ข้อมูลและหลักฐานของทุกแหล่งยังอยู่ ย้อน (undo) ได้

## 6. Quantity Aggregation
- **ยังไม่ตัดสิน:** ไม่ลดยอด (ทุกแหล่งยังถูกนับในยอดชั่วคราว) แต่ไม่มีแหล่งไหนถูกปล่อยยอด
- **ลิงก์แล้ว:** ยอดรวม, BOQ แผ่น 1, ปร.4 และเทียบ BOQ นับครั้งเดียว เพราะทุกจุดตัด REJECTED ออก และ `zeroOut` ตั้งปริมาณเป็น 0
- **แยกเป็นคนละชิ้น:** นับครบทุกแหล่ง
- **หลักฐานจากเบราว์เซอร์ (BOQ แผ่น 1 จากไฟล์เดียวกัน):** ก่อนลิงก์ **0.864** ลบ.ม. → หลังลิงก์ **0.432** ลบ.ม.

## 12. Known Limitations
- **ยอดชั่วคราวยังนับทุกแหล่ง:** ระหว่างยังไม่ตัดสิน ยอดรวมในหน้าจอและ Excel เป็นยอดชั่วคราวที่อาจนับซ้ำ (ตั้งใจ — ห้ามลดเองโดยไม่มีหลักฐาน) แต่ทุกแหล่งถูกกันไม่ให้ปล่อยยอด
- **กรณีผังหลายตำแหน่ง + แถวตาราง (INSUFFICIENT_EVIDENCE):** ลิงก์ไม่ได้เพราะจะรวมหลายตำแหน่ง ถ้าแถวตารางเป็นแค่ตารางสรุปของชิ้นในผัง ผู้ตรวจต้องใช้ "ไม่นับรายการนี้" (การตัดสินเดิม) กับแถวตาราง แล้วเลือก "คนละชิ้น" ให้กลุ่ม — ยังไม่มีตัวเลือก "แถวนี้เป็นตารางสรุปของชิ้นในผัง" โดยตรง
- **แหล่งที่ถูกนับเลือกเองไม่ได้:** ระบบนับที่แหล่งแรก (index ต่ำสุด) เสมอ; ค่าต้องเหมือนกันจึงลิงก์ได้ ยอดจึงไม่ต่าง แต่หลักฐานที่ผูกกับยอดคือแหล่งแรก
- **PDF + DXF:** ไม่มีทางเกิดใน flow ปัจจุบัน
- **กฎตำแหน่งซ้ำเดิม** (ชั้น + กริด + tag) ยังตัดรายการซ้ำอัตโนมัติเหมือนเดิม: มีหลักฐานตำแหน่งแต่ไม่มีผู้ตรวจยืนยัน — ไม่ได้เปลี่ยนเพื่อไม่กระทบปริมาณเดิม
- **ผลกับแบบจริง:** ยังไม่ได้วัดว่าแบบจริงมีกลุ่มซ้ำกี่กลุ่ม (benchmark ไม่บันทึก flag)

## 13. Remaining Risks
- ถ้าแบบจริงมีแถวตารางเบอร์เดียวกันจำนวนมากคนละหน้า (เช่น ตารางแยกตามชั้น) ทุกกลุ่มจะต้องให้ผู้ตรวจตัดสิน: ภาระงานเพิ่ม แต่ไม่นับซ้ำเงียบ
- ข้อความแถวที่ OCR อ่านต่างกันเล็กน้อยทำให้ค่าต่างกัน → CONFLICTING_SPECIFICATION (ปลอดภัย แต่ต้องตัดสินค่าก่อน)
- ผู้ตรวจยังไม่ยืนยันตัวตน และ fingerprint ไม่มีลายเซ็น (จากรอบก่อน)
